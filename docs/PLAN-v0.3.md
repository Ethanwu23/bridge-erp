# Bridge 开发计划与任务拆分（V1 只读版）

| 项 | 内容 |
|---|---|
| 文档版本 | v0.3（待评审） |
| 日期 | 2026-11-01 |
| 对应 PRD | v0.5（开发基线） |
| 对应架构 | v0.2 |
| 周期 | 6 周（W1–W6） |
| 团队 | 1 名全栈 |

## 1. 交付目标与里程碑

| 里程碑 | 时间 | 验收标准 |
|---|---|---|
| M1 查数可用 | W3 末 | 5 个指标端到端可问；结果带口径与明细 |
| M2 内部试用 | W6 末 | 10 个内部试用账号；审计可查；准确率 ≥ 95% |

**范围基线**：8 条 P0（FR-01 ~ FR-08），只读，无草稿、无导出。

## 2. 产能与假设

- 6 周 × 5 天 = 30 个工作日；按 80% 有效工时 = **24 个有效人日**。
- 已排任务 **23 人日**，保留 **1 人日**缓冲。
- 每周节奏：4 天开发 + 1 天联调/文档/缓冲；不排并行任务，单线程推进。

## 3. 开发流程（单人版）

| 环节 | 做法 |
|---|---|
| 分支 | `main` 可部署；`feat/*` 生命周期 ≤ 2 天 |
| 提交 | `feat/fix/docs/test(scope): 描述`，一次提交只做一件事 |
| 自检 | 每个功能完成即写 3 条手工验证步骤，记录在 `docs/checks.md` |
| 评审 | 单人项目用"周五 Demo + 验收标准逐条过"代替代码评审 |
| CI | ruff + pytest + 前端 tsc，PR 必须全绿；构建镜像 |
| 环境 | dev（本地 ERPNext 容器）→ staging（预发）→ prod（正式验证环境） |
| DoD | 验收标准可演示、有单测、审计埋点、文档同步 |

**周五 Demo 固定检查**：

1. 本周功能在 staging 演示一遍。
2. 对照验收标准逐条打勾。
3. 更新下周任务与风险。

## 8. 风险与缓冲

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 指标签字延迟 | W1 周三未确认 | 先用行业默认口径，标注"待确认" |
| ERP API 限流 | 压测出现 429 | 降低单页条数、加缓存 |
| Token 授权受阻 | W5 前未拿到 | 服务账号降级，审计标记 |
| 单人排满 | 任一任务延期 | 优先保"3 个指标可问"，其余顺延 |

**缓冲**：24 人日中排 23，留 1 人日；W5 部署周本身也承担兜底。
