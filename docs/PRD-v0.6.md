## 1. 一页纸摘要

**问题**：销售查一个数要问 IT，等报表、等口径；通用大模型不懂"回款率""逾期应收"的定义，直接问就会编。

**方案**：在 ERP 和 AI 之间加一层 Bridge——把 5 个销售指标的口径与取数逻辑固化成模板，AI 只负责把问题翻译成"指标 + 时间 + 过滤"，执行与聚合**全部走确定性模板**。

**V1 只做两件事**：

1. **查数**：自然语言问 5 个销售指标，返回数值 + 口径 + 明细。
2. **留痕**：每次问答可回放，知道数是怎么算出来的。

**V1 明确不做**：单据草稿、导出、写库、多 Agent、多 ERP 适配、页面抓取。

**成功标准（6 周内部验证，10 个试用账号）**：周活 ≥ 10 人；查数准确率 ≥ 95%；字典外问题 100% 拒答；未授权访问 0 起。

### 1.1 为什么砍到这么小

- **1 个人 6 周，只有 24 个有效人日**。草稿需要模板、抽取、校验、导出四块，单独就要 7 人日以上，放进来必然两头不靠。
- **先证明"查得准"**。准确率是这类产品唯一的信任基础；口径错了，功能再多也没人用。
- **草稿是 V1.1 的第一优先级**。本版把语义层、适配器、审计都打好，V1.1 加草稿只需增量，不用返工。

## 2. 背景与问题

| 现象 | 证据 |
|---|---|
| 原厂 AI 也只敢做只读 | Odoo 19 的 Ask AI 明确"不能修改数据库"，写操作要自定义 Agent 与服务端动作 |
| 客户要的是可控、可私有化 | ERPNext 社区提案要求原生 DeepSeek 集成，理由直指隐私、成本与开源一致性 |
| 通用大模型答不准业务问题 | 口径、权限、数据范围散落在 ERP 与人的经验里，模型无从得知 |
| 销售最常问的就那几个数 | 销售额、回款、订单、逾期——高频、重复、口径固定，最适合先做 |

## 3. 目标与非目标

| 目标 | 衡量方式 |
|---|---|
| 销售自助查数 | 查数请求中 70% 不再经过 IT |
| 口径一致 | 与 ERPNext 报表核对一致率 ≥ 95% |
| 建立可信边界 | 100% 操作可回放，0 起越权 |
| 验证可复制性 | 6 周跑通 ERPNext，形成接入手册 |

**非目标（V1 不做）**：

- 不做单据草稿、导出、写库、审批。
- 不做多 Agent、A2A、插件市场。
- 不覆盖采购、库存、财务等销售以外的域。
- 不做模型训练与微调。
- 不做移动端原生 App（先用 Web + 企微内嵌）。

## 4. 用户与角色

| 角色 | 典型诉求 | V1 提供 |
|---|---|---|
| 销售（客户经理） | 快速查客户/订单/回款，不想等 IT | 5 个指标问答、口径说明、明细 |
| 销售主管 | 看清团队业绩与风险 | 指标问答、按客户/区域下钻 |
| IT 管理员 | 可控、可审计 | 权限映射、审计日志、回放 |

## 5. 核心场景

### 5.1 场景 A：销售指标问答

**用户故事**：作为销售，我想直接问"本月华东区回款率是多少，哪些客户拖了后腿"，不想等 IT 出报表。

**主流程**：

1. 用户输入问题（Web / 企微）。
2. 系统识别指标、时间、过滤条件，生成查询计划。
3. 按用户身份调用 ERPNext API，权限由 ERP 裁决。
4. 返回数值 + 口径说明 + 明细列表。
5. 用户点击"有用/无用"，进入评测样本。

**验收标准**：

| 项 | 阈值 |
|---|---|
| 口径与 ERPNext 报表一致率 | ≥ 95%（30 条抽样） |
| 字典外问题拒答率 | 100%（不编造） |
| 响应时间 | P95 ≤ 10 秒 |
| 明细可用率 | 100%（受权限约束） |

### 5.2 场景 B：审计与回放

**用户故事**：作为 IT 管理员，我要能还原"某次回答是怎么来的"，用于答疑与合规检查。

**主流程**：按用户/时间筛选 → 查看问题、查询计划、API 调用、数据范围、模型与耗时 → 查看完整 JSON。

**验收标准**：trace 完整率 100%；可还原问题、计划、API 调用与结果。

## 6. 产品方案

### 6.1 最小架构

**请求链路**：用户（Web / 企微）→ Bridge 单体服务 → ERPNext REST API → 结果回传

| 层 | 组件 | 职责 |
|---|---|---|
| 接入 | ERPNext REST API、用户 Token | 取数、取元数据、认人 |
| 语义 | 3 个对象、5 个指标、权限映射 | 让 AI 懂业务口径 |
| 引擎 | 查询引擎 | 解析、校验、执行、聚合 |
| 治理 | 身份、审计、回放 | 可追溯、可拦截 |
| 交互 | Web 页面 / 企微内嵌 | 不改变用户现有入口 |

V1 是**单体 + 全 API**，不复制数据、不直连数据库、不引入队列。

### 6.2 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 版本基线 | ERPNext v16 为主；接受跟随客户现网版本 | 新项目从主线起步；跟随现网可免升级 |
| 数据接入 | 全部走 ERPNext REST API | 通用适配；权限天然；无需 DBA 配合 |
| AI 身份 | 每用户 API Token，权限由 ERPNext 裁决 | 不共享服务账号，越权可拦截 |
| 查询方式 | 指标模板 + LLM 填槽位 | 模型不生成查询，准确率可控 |
| 写入 | 无写接口，只读 | 零风险，先证明价值 |
| 交付 | 内部验证环境，Docker Compose 单机 | 探索阶段先跑通闭环，客户交付形态待定 |

### 6.3 与 ERP 的边界

- **读**：全部通过 ERPNext REST API，按用户 Token 鉴权。
- **写**：V1 没有任何写接口。
- **权限**：ERPNext 是最终裁决方；Bridge 只做前置过滤与展示裁剪。
- **不支持**：数据库直连、页面 DOM 抓取、鼠标模拟。

## 7. 功能需求

| 编号 | 模块 | 功能 | 说明 | 优先级 |
|---|---|---|---|---|
| FR-01 | 接入 | ERPNext 连接与鉴权 | 每用户 API Token；IT 不接受时降级服务账号；支持连接测试 | P0 |
| FR-02 | 接入 | 元数据同步 | 拉取 3 个 DocType 的字段与枚举，手动 + 每日增量 | P0 |
| FR-03 | 语义 | 指标字典 | 5 个指标：口径、公式、负责人、版本 | P0 |
| FR-04 | 语义 | 对象语义与权限映射 | 3 个对象的中文名、同义词、字段敏感级、角色范围 | P0 |
| FR-05 | 问答 | 意图解析与校验 | 自然语言 → 指标/时间/过滤；白名单校验 | P0 |
| FR-06 | 问答 | 查询执行与结果 | 调用 API、聚合、数值 + 口径 + 明细 | P0 |
| FR-07 | 问答 | 拒答与澄清 | 字典外/歧义时反问或拒答 | P0 |
| FR-08 | 治理 | 身份、审计与回放 | Token 透传、全量日志、trace 查看 | P0 |

## 8. 治理与安全

### 8.1 权限模型

工具可见性 = 用户权限 ∩ 项目授权。AI 不拥有独立权限，**它就是当前用户**。

### 8.2 V1 风险分级（只有一级）

| 级别 | 示例 | 策略 |
|---|---|---|
| `READ` | 查订单、查回款、查逾期 | 自动执行，记录数据范围 |

> V1 不产生 `WRITE` 与 `IRREVERSIBLE` 事件；草稿类 `DRAFT` 随 V1.1 一起设计。

### 8.3 审计字段

`trace_id`、用户、租户、问题原文、查询计划、API 调用记录、数据范围、模型与版本、耗时、Token、结果摘要、用户反馈。

## 9. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 查数 P95 ≤ 10s |
| 可用性 | 99.5%（试用期） |
| 并发 | 10 并发用户 |
| 安全 | 传输加密、字段脱敏、审计不可篡改 |
| 部署 | 内部验证环境 Docker Compose，4C8G 起步 |
| 数据保留 | 审计 180 天，会话 90 天 |

## 10. 指标

- **北极星**：周有效使用次数（有效 = 查看结果或展开明细）。
- 查数准确率、拒答正确率、平均节省时间、单次成本。

## 11. MVP 计划（6 周，1 人）

| 周 | 交付 | 关口 |
|---|---|---|
| W1 | 接入与语义：连接、元数据、3 对象、5 指标、5 模板 | API 连通、指标签字 |
| W2 | 查询引擎：解析、校验、执行、聚合、拒答 | 5 个指标可答 |
| W3 | 前端与联调：对话、结果卡、明细 | 端到端可用 |
| W4 | 审计与评测：trace、30 条评测集 | 准确率 ≥ 90% |
| W5 | 修正、部署、预演 | 准确率 ≥ 95%、客户环境可起 |
| W6 | 内部试用（10 个账号）与复盘 | 首周无阻断问题 |

## 12. 风险与已确认决策

| 风险 | 影响 | 缓解 |
|---|---|---|
| 1 人排满，无缓冲 | 延期直接挤压评测 | 只做 5 指标；钻取与回放保持最简；W5 留作兜底 |
| API 聚合能力不足 | 复杂指标算不出 | 只用能算的 5 个；优先报表接口 |
| 用户 Token 授权受阻 | 上线卡在 IT | 提前确认；准备服务账号降级 |
| 模型幻觉 | 答错数据 | 只答 5 个指标；拒答优先；结果附 API 调用 |
| 试用没人用 | 验证失败 | 嵌入企微；首屏放高频问题；找愿意尝鲜的销售带头 |

**已确认决策（v0.5）**：

| 决策 | 结论 | 依据 |
|---|---|---|
| 范围 | 只读 5 指标，无草稿 | 1 人 6 周只有 24 有效人日，草稿放 V1.1 |
| 指标 | 销售额、回款额、回款率、订单数、逾期应收 | 销售最高频、口径最稳定 |
| 团队 | 1 名全栈 | 前后端同一人，减少协作成本 |
| 版本 | v16 为主，接受跟随客户现网 | 降低客户升级成本 |
| 授权 | 每用户 Token 为主，服务账号降级 | 权限落人、审计可追溯 |

以上决策已于 2026-11-01 复核确认，无遗留待定项；v0.5 作为开发基线。

### 13.1 术语

| 术语 | 含义 |
|---|---|
| 语义层 | 对象、字段、指标、权限的机器可读定义 |

### 13.2 指标清单（V1 范围，5 个）

| 指标 | 口径 | 主要来源 |
|---|---|---|
| 销售额 | 发票含税合计（可切换不含税） | Sales Invoice |
