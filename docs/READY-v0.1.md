# Bridge 开工前置检查与阻塞项闭环

| 项 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 日期 | 2026-11-01 |
| 对应 PRD | v0.5（开发基线） |
| 项目性质 | 探索项目，无真实客户 |
| 结论 | 三个阻塞项全部可自闭环，D1 完成即可进 W1 |

## 1. 结论

原判断里的三个"硬阻塞"都建立在"有真实客户"的前提上。项目改为探索性质后，它们的性质变了：

| 原阻塞 | 原假设 | 新判断 |
|---|---|---|
| 客户 ERP 环境与 Token | 需客户 IT 配合 | **自建本地 ERPNext v16 实例**，自己开 Token |
| 5 个指标口径签字 | 需销售运营拍板 | **自定"V1 假设口径"并版本化**，对外演示时标注假设 |
| 模型接入 | 客户提供 Key/内网地址 | **DeepSeek 官方 API**，环境变量注入 |

三项都能在 1 天内闭环，因此**结论改为：可以进入开发流程**，但 D1 仍要走一遍检查清单（见第 7 节），确认"环境起得来、数据算得对、模型调得通"。

## 2. 阻塞项处置

| 原阻塞 | 处置方案 | 验证方法 | 耗时 |
|---|---|---|---|
| 无 ERP 环境 | 本地 Docker 起 ERPNext v16.53.0，自建站点与账号 | 浏览器能登录、API 能取数 | 0.5 天 |
| 无业务口径 | 按 ERPNext 标准字段定义 5 个指标，形成 V1 假设口径 | 用种子数据手算期望值，与 API 结果比对 | 0.3 天 |
| 无模型 Key | DeepSeek 官方 API，`deepseek-flash`，Key 走环境变量 | 一次 JSON 输出调用成功 | 0.2 天 |

**风险变化**：不再是"等外部"，而是"自建环境与真实客户有差异"。缓解办法是种子数据覆盖边界场景（退货、跨期回款、部分收款、逾期），并在 PRD 里保留"口径可配置、可替换"的设计。

## 3. 环境：本地 ERPNext

### 3.1 启动方式

官方 `frappe_docker` 提供 `pwd.yml`，镜像已是 `frappe/erpnext:v16.53.0`，与 PRD 的版本基线一致：

```bash
git clone https://github.com/frappe/frappe_docker
cd frappe_docker
docker compose -f pwd.yml up -d
```

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| frontend | frappe/erpnext:v16.53.0 | 8080 | Nginx + 前端入口 |
| backend | 同上 | 内网 | Gunicorn |
| db | mariadb:11.8 | 内网 | 数据库 |
| redis-cache / redis-queue | redis:6.2-alpine | 内网 | 缓存与队列 |
| scheduler / websocket | frappe/erpnext:v16.53.0 | 内网 | 定时任务与实时 |

- 访问：`http://localhost:8080`
- 站点：`frontend`；管理员：`Administrator` / `admin`
- 首次启动会自动建站并安装 ERPNext（无演示数据，正好由我们自建）

### 3.2 生成 API Token

1. 登录后进入 **用户 → Administrator → API Access → Generate Keys**。
2. 得到 `api_key` 与 `api_secret`（secret 只显示一次）。
3. 验证：

```bash
curl -s -H "Authorization: token <api_key>:<api_secret>" \
  "http://localhost:8080/api/resource/Sales%20Invoice?limit_page_length=1"
```

返回 `{"data": []}` 即连通（此时还没有数据）。

### 3.3 与真实客户的差异

| 差异 | 影响 | 处理 |
|---|---|---|
| 无自定义字段 | 真实客户常有自定义字段 | 语义层支持字段映射，V1.1 再接真实实例 |
| 权限模型为标准 Role | 客户可能有 User Permission 行级限制 | 适配器透传 Token，权限逻辑不写死 |
| 数据量为零 | 性能测试无真实量级 | 种子数据造 1,000 张发票做压测 |

## 5. 指标口径（V1 假设口径）

没有业务方签字，口径由技术侧按 ERPNext 标准字段定义，版本化保存，对外演示标注"假设口径"。

### 5.1 定义

| 指标 | 口径 | 字段与来源 |
|---|---|---|
| 销售额 | 期间内已提交发票的含税合计，退货按负数计入 | `Sales Invoice.base_grand_total`，`docstatus=1`，`posting_date` 在区间 |
| 回款额 | 期间内已提交收款单的实收金额 | `Payment Entry.base_paid_amount`，`payment_type='Receive'`，`docstatus=1` |
| 回款率 | 期间回款额 ÷ 同期销售额 | 上式两项相除 |
| 订单数 | 期间内已提交销售订单笔数 | `Sales Order`，`docstatus=1`，`transaction_date` 在区间，计数 |
| 逾期应收 | 已过到期日且未收完的余额合计 | `Sales Invoice.base_outstanding_amount > 0`，`due_date < 今天`，`docstatus=1` |

### 5.2 边界规则

| 规则 | 说明 |
|---|---|
| 只认 `docstatus=1` | 草稿（0）与已取消（2）一律排除 |
| 用 `base_*` 字段 | 多币种统一折算为公司本位币，避免混币种相加 |
| 日期含首尾 | `posting_date` 取 `[from, to]` 闭区间 |
| 退货负数 | `is_return=1` 的发票金额为负，直接相加 |
| 跨期回款 | 分子按回款日期、分母按开票日期，允许比率 > 100%，结果页必须提示 |
| 时区 | 以 ERPNext 站点时区为准，前端不二次换算 |

### 5.3 API 取数形态

```text
GET /api/resource/Sales Invoice
  ?filters=[["docstatus","=",1],
            ["posting_date",">=","2026-10-01"],
            ["posting_date","<=","2026-10-31"]]
  &fields=["name","base_grand_total","base_outstanding_amount","posting_date","due_date","is_return"]
  &limit_start=0&limit_page_length=100
```

回款、订单同理。单页 100 条，超过则分页累加；超过 5,000 行走报表接口或提示缩小范围。

## 6. 模型接入：DeepSeek

### 6.1 配置

| 项 | 配置 | 值 |
|---|---|---|
| Base URL | OpenAI 兼容 | `https://api.deepseek.com` |
| 模型 | 快模型，够用 | `deepseek-flash` |
| 输出格式 | JSON Output | `response_format={"type":"json_object"}` |
| 温度 | 槽位填充要稳定 | `temperature=0` |
| 最大输出 | 只输出一个 JSON | `max_tokens=300` |
| 超时与重试 | 失败降级 | 10s，重试 1 次 |
| Key 管理 | 环境变量 | `DEEPSEEK_API_KEY`，不落库、不进镜像 |

### 6.2 成本估算

按官方 2026-11 价格（`deepseek-flash`，非高峰）：输入 cache miss $0.15/百万 token，输出 $0.6/百万 token。

| 项 | 估算 |
|---|---|
| 单次输入 | 约 1,200 token（系统提示 + 5 指标定义） |
| 单次输出 | 约 150 token |
| 单次成本 | ≈ $0.00027，约 ¥0.002 |
| 日成本（200 次） | ≈ ¥0.4 |
| 月成本 | ≈ ¥12 |

指标定义固定，可命中上下文缓存，实际成本更低。

### 6.3 降级

| 场景 | 降级策略 |
|---|---|
| 无 Key / 调用失败 | 规则解析：关键词匹配 5 个指标（"回款"→回款率、"逾期"→逾期应收） |
| 输出非 JSON | 重试 1 次；仍失败则返回澄清话术 |
| 输出指标不存在 | 拒答 + 候选指标，不猜测 |
